# 任务

你在为一个细胞生物学与人工智能交叉方向的论文索引站写单篇论文的「图解」底稿。材料包是这篇论文的全部已知信息：题录、中文摘要、英文摘要、核心要点、结构化分析、代码摘要、论文全文。读者是生物医学研究者与有工程背景的读者，他们打开一页就要明白：这篇论文解决了什么困难、方法怎么运转、凭什么可信、什么情况下不成立。

# 材料的使用

只使用材料包里出现的信息。材料包没有写到的事实、数字、数据集名称、结论，一律不写。论文全文是被压成单行的纯文本，章节标题可能丢失，根据上下文判断方法、实验、结论的位置。

数字、数据集名称、指标名称保留原文写法，不做换算、不做四舍五入、不改单位。中文里保留英文术语（如 attention、diffusion、scRNA-seq），第一次出现时给出中文解释。

# 输出

只输出一个 JSON 对象，不要 Markdown 代码块，不要任何解释文字。字段如下，所有字符串使用简体中文（英文术语除外）。

{
  "title_zh": "论文标题的中文表述，30 字以内",
  "one_line": "一句话结论，28 字以内，结尾不加句号。说清这篇论文做到什么、对谁有用。不要以“本文”“该论文”开头。",
  "problem": "它要解决的困难，2 句，90 字以内。写清楚此前的方法卡在哪里。",
  "intuition": "直观点子，2 到 3 句，120 字以内。用读者已有的经验解释核心想法。",
  "structure": "linear | encoder_decoder | iterative | branch_merge | retrieval 五选一",
  "stages": [
    {"name": "阶段名，6 字以内", "action": "动词开头的动作，10 字以内", "detail": "这一步做什么、为什么这样做，50 字以内", "input": "输入，12 字以内", "output": "输出，12 字以内"}
  ],
  "key_facts": [
    {"label": "指标名，6 字以内", "value": "数值带单位，8 字以内", "note": "它意味着什么，20 字以内"}
  ],
  "metrics": [
    {"name": "指标名，10 字以内", "dataset": "数据集，14 字以内", "ours": "本方法数值", "baseline": "对比方法数值", "delta": "差值或提升幅度", "unit": "单位，如 %、×、h"}
  ],
  "design_choices": [
    {"choice": "采用的设计，14 字以内", "alternative": "另一个选项，14 字以内", "reason": "为什么这样选，60 字以内"}
  ],
  "limits": ["失效条件或局限，50 字以内"],
  "takeaway": "读者该记住的一句，40 字以内",
  "terms": [
    {"en": "English term", "zh": "中文名", "note": "一句话解释，30 字以内"}
  ],
  "evidence": [
    {"claim": "这一页依赖的判断，30 字以内", "quote": "材料包中的连续原文片段，30 到 180 字，逐字复制"}
  ]
}

# 字段要求

stages 写 3 到 5 个，必须覆盖从输入到输出的完整链路，每一步有明确的输入与输出。name 用动宾短语或名词短语，不要写“第一步”。

key_facts 写 3 到 6 个，取自论文报告的关键数字（数据规模、提升幅度、耗时、参数量、样本数）。value 保留原文的数字与单位，note 说明这个数字的含义。

metrics 写 0 到 4 条，只收论文明确给出的对比数字（本方法、对比方法、数据集、单位齐全）。同一篇论文的多条 metrics 尽量使用同一单位，便于成图。没有可比数字时给空数组。

design_choices 写 2 到 4 条，每条是一个真实的取舍：采用的设计、被放弃的选项、选择的原因。reason 要写出机制层面的原因，不要写“效果更好”。

limits 写 3 条，来自作者承认的局限、实验覆盖不到的条件、对数据或算力的依赖。

terms 写 3 到 5 个，是本页出现的关键术语。

evidence 写 4 到 6 条，quote 必须是材料包中连续出现的原文，逐字复制，不改写、不翻译、不加省略号。优先引用摘要、方法开头、实验结果段落中的句子。claim 用中文概括这条原文支撑了什么。

# 语言

使用只有中小学文化水平也能看懂的词。句子短，一句话一个意思。不使用“综上所述”“总而言之”“值得注意的是”“不仅……而且……”这类套话。不使用“不是……而是……”的对比句式。不使用“赋能”“抓手”“闭环”“范式转变”这类词。headings 与句子都直接陈述结论。

# 自检

用词禁忌：「落地」「对齐」「钉死」「技术栈」「闭环」「赋能」「综上所述」「总而言之」「值得注意的是」「不是……而是……」全部不许出现，对应关系写「一一对应」「同一套坐标」。

输出前逐条核对：one_line 是否说明了做到什么；stages 是否每一步都有输入输出；metrics 的每个数字是否在材料包中原样出现；evidence 的每条 quote 是否能在材料包中逐字找到；limits 是否具体到条件而不是“仍需进一步研究”。
