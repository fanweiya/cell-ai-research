Methods Task construction Our benchmark comprises 121 tasks, each requiring an agent to register two or more spatial transcriptomics sections into a common coordinate system. Tasks were compiled using Paper2Bench, an automated pipeline that translates published benchmarks and methods papers into executable task packages. The pipeline extracts experimental units from figures, tables, methods, code, and public repositories; attaches deterministic scoring profiles; generates task prompts without exposing held-out evaluation data; and constructs isolated agent workspaces. Candidate tasks must pass a suite of deterministic validation checks before inclusion (Supplementary Note 1). The 121 tasks span five task families derived from three sources: serial tissue sections, a primary motor cortex (MOp) series, and cross-platform section pairs from SABench [ 11 ] ; rotation, cropping, and three-dimensional reconstruction tasks from GEASO [ 14 ] and the whole-mouse-brain MERFISH atlas; and synthetic tissues generated with the Albis simulator [ 57 ] (Supplementary Tables 1 , 2 and 3 ). Ground-truth spatial coordinates are available for 32 tasks and cell-type or anatomical region annotations for 69 tasks, while the remaining tasks are evaluated using gene expression similarity. For each task, the agent receives sanitized h5ad files containing only the expression matrix, feature metadata, anonymized observation identifiers, and spatial coordinates. The agent outputs one CSV table of aligned ( x , y ) (x,y) coordinates per section, with the reference section retaining its original positions. Published methods and baselines We re-executed 13 published spatial alignment packages—CAST [ 53 ] , GEASO [ 14 ] , GPSA [ 47 ] , moscot [ 55 ] , PASTE [ 45 ] , PASTE2 [ 46 ] , SANTO [ 54 ] , SLAT [ 48 ] , SPACEL [ 51 ] , Spateo [ 52 ] , STAIR [ 56 ] , STalign [ 49 ] , and STAligner [ 50 ] —across 41 parameter configurations on the same task inputs [ 11 , 14 ] and the simulated tissue suite [ 57 ] . The execution was assisted by coding agents and verified by human inspection and checks to make sure the reproduced values are close to prior reported values whenever possible [ 11 , 14 ] . On each task, the best published baseline is defined as the top-scoring configuration across all packages. We also evaluated three geometric baselines across all 121 tasks: an identity baseline (unaligned coordinates) and similarity transformations estimated by principal component analysis (PCA) and iterative closest point (ICP) registration. Software versions, parameter configurations, and comparisons with originally published values are detailed in Supplementary Note 2 and Supplementary Figure 1 . Agents, prompting conditions, and execution harness We evaluated six frontier LLMs through their respective command-line coding interfaces: Claude Code ( claude-opus-5.5 and claude-sonnet-5.5 ), Codex CLI ( gpt-6-astra and gpt-5.5 ), and Gemini CLI ( gemini-4-argon and gemini-3.5-flash ) (Supplementary Table 4 ). All agents were executed in non-interactive mode with permission prompts bypassed, no custom system instructions, and a clean environment per run. Our primary analysis mimics a low-overhead setting for scientists, referred to as the basic prompt condition: the workspace contained only the input data, task specification, and a standard scientific Python environment ( numpy , scipy , pandas , scikit-learn , and h5py ), without any domain-specific alignment packages installed or referenced. We assessed the sensitivity of agent performance under the rich-context condition, where published alignment packages were pre-installed in isolated environments and the prompt was augmented with usage guidelines, API examples, package documentation, and literature-derived recommendations summarizing which tool families performed best for each data modality in prior benchmarks (Supplementary Note 3). Every run executed inside an isolated Singularity container [ 58 ] with read-only software and data mounts, a single writable workspace directory, and no access to held-out evaluation files. Primary analyses use the first completed, scored run for each model, task, and prompting condition. Run cost was recorded as the API-equivalent expenditure reported by Claude Code and calculated from token usage at standard API list prices for OpenAI and Google models. Leakage prevention and auditing Workspace inputs were constructed using a strict allowlist that stripped cell-type annotations, ground-truth coordinates, and auxiliary metadata, while anonymizing cell identifiers and randomly permuting row order. Following each run, an automated audit scanned the execution trace, workspace files, and submitted outputs for references to restricted filesystem paths, withheld metadata field names, or credentials (Supplementary Note 4, Supplementary Figure 2 and Supplementary Table 5 ). Evaluation metrics and scoring Scoring was executed outside the Singularity container after agent termination across all designated section pairs in each task, as preliminary pilots showed that exposing the scorer inside the workspace led agents to inspect or modify the scoring function. Coordinate error was quantified as the mean absolute error (MAE) between submitted and ground-truth coordinates. Label agreement was evaluated on spatially matched cells across aligned sections using nearest-neighbor label matching accuracy, anatomical region overlap (alpha-shape intersection over union), and mutual nearest-neighbor (MNN) label concordance [ 11 , 14 ] . Expression agreement was quantified on a spatial grid over the overlap region using gene-wise Pearson correlation, cosine similarity, and structural similarity (SSIM). Each task’s primary metric was coordinate error when ground-truth positions were available and the composite agreement score (mean of expression and label metrics) otherwise. Formal metric definitions and numerical parity checks against the original SABench codebase are provided in Supplementary Note 5. Strategy distillation and cross-validation To test whether agent-discovered workflows could be consolidated into a standalone algorithm, we performed five-fold cross-validation under both random task splits and task-family holdouts. For each fold, an isolated instance of Claude Code ( claude-opus-5.5 ) was provided with the final scripts and training scores of claude-opus-5.5 and gpt-6-astra from the four training folds and instructed to synthesize a single, general-purpose Python alignment program. The resulting program was then executed on the held-out fold without any LLM calls and graded by the benchmark scorer, with runtime crashes or invalid outputs scored as failures (Supplementary Note 3). Statistical analysis We partitioned variance in alignment accuracy, runtime, and cost across task, model, prompt condition, and replicate runs using factorial analysis of variance (ANOVA). A run was considered to match or outperform the best published baseline if its primary score equaled or exceeded the highest score achieved by any published package configuration on that task. Confidence intervals and hypothesis tests were computed via cluster bootstrap resampling (Supplementary Note 6). Execution trace analysis Agent execution logs were parsed into sequential tool-call steps and classified into eight operational phases (such as data inspection, method exploration, candidate evaluation, and output validation), alongside 48 fine-grained algorithmic tags applied to both intermediate scripts and final submitted code (Supplementary Note 7 and Supplementary Figures 3 and 4 ). Results Translating published benchmarks into auditable agent tasks We compiled executable agent tasks from two spatial transcriptomics alignment studies: SABench [ 11 ] and GEASO [ 14 ] ( Figure 1 a). Each component of a source paper maps to a machine-readable task card: dataset tables specify input sections, experimental protocols define section pairings and geometric perturbations, evaluation code defines the scorer, and benchmarked tools provide the reference baselines ( Figure 1 b). During execution, an agent observes only sanitized gene expression matrices, spatial coordinates, task instructions, and the required output schema, while ground-truth coordinates, cell-type annotations, and scoring scripts remain hidden. We reconstructed 98% of the tasks used in SABench (source data are not directly available for download for the remainder) and verified that our scorer matched the authors’ evaluation results to within 10 − 7 10^{-7} (Supplementary Note 1). After grouping simulated tissues from the same source section and serial alignments within the same dataset, our benchmark spans 121 tasks across 19 datasets and five task families ( Figure 1 c): cross-platform section pairs, serial sections, simulated tissues with known positions, geometric stress tests (rotations, crops, and partial overlaps), and three-dimensional reconstructions of up to 129 sections. Rebuilding the published evaluations from raw inputs also uncovered a 20-fold coordinate unit mismatch between ground-truth and input positions in the published evaluation of the Drosophila embryo stack (Supplementary Note 1). Figure 1 d illustrates a representative three-dimensional reconstruction task requiring registration of 129 scrambled MERFISH sections of a mouse hemibrain across six evaluated frontier coding agents. The top published baseline on this task, SPACEL, left a mean coordinate error of 846 spatial units, whereas gpt-6-astra reduced the error to 0.13 in 30 tool calls (32 minutes; $2.91). Trace inspection shows that the agent chained pairwise rigid alignments across adjacent sections, detected cumulative rotational drift along the stack, and enforced a global constraint along the straight medial boundary of the hemibrain. Notably, however, gene-expression-based evaluation metrics ranked SPACEL equal to this near-exact reconstruction, illustrating a potential discrepancy between proxy scores and coordinate-based scores. Preventing benchmark leakage through container isolation In an initial pilot where evaluation scripts and ground-truth files resided on the shared filesystem outside the workspace—even with prompts explicitly instructing agents not to search parent directories—trace audits revealed four modes of test leakage (Supplementary Table 5 ). Agents traversed the filesystem to copy ground-truth coordinate files, inspected or modified the scoring script, reused outputs from concurrent runs, or extracted precomputed results bundled with cloned method repositories. We therefore isolated every run inside the Singularity container ( Figure 1 a, step 3) with read-only mounts and no access to held-out data or scoring code, followed by an automated post-run trace and workspace audit (Supplementary Figure 2 ). We then manually searched for potential answers and ground-truth file names in the logs and generated files, and confirmed that the resulting runs did not search for the ground truth or exhibit obvious model hacking behavior such as rewriting scoring files (Supplementary Note 4). Top agent solutions outperform published baselines The best AI agents consistently matched or outperformed state-of-the-art spatial alignment methods, achieving lower error on 79% of tasks with ground-truth positions ( Figure 2 a). Across all 118 tasks evaluated by expression agreement, the best agent matched or beat the top published method on 57% of tasks, driven by strong gains on cross-platform pairs (41 of 45; Figure 2 b), with robust win rates across other expression and label metrics (Supplementary Figure 1 e). Among AI agents, however, performance varied substantially by model version, falling roughly into three tiers: gpt-6-astra and gemini-4-argon ; followed by claude-opus-5.5 , gpt-5.5 , and claude-sonnet-5.5 ; and finally gemini-3.5-flash . Stronger models also produced more reproducible results across replications , as they were more likely to converge on the same solution strategies ( Figure 2 c,d), with rank correlations across runs of ρ = 0.63 \rho=0.63 , 0.71 0.71 – 0.74 0.74 ( 0.13 0.13 – 0.14 0.14 ), and 0.93 0.93 ( 0.10 0.10 ) for gemini-3.5-flash , the Claude models, and gpt-6-astra , respectively (Supplementary Figure 5 and Supplementary Note 8). Reproduction of published baselines Benchmarking the 16 published baselines showed that no single baseline method dominated across every tissue regime (Supplementary Note 2 and Supplementary Figure 1 a–d). Pooled across all task families, SLAT led overall, followed by Spateo and CAST. This largely agrees with previous benchmark results [ 11 ] , with the caveat that the best method varied by regime: SLAT led on serial sections and on simulated misalignment due to rotation and cropping, Spateo performed best on the motor cortex series, CAST on cross-platform pairs, and STalign on simulated tissues. Interestingly, custom agent solutions often dramatically reduced coordinate error in large-scale three-dimensional serial alignment, on both simulated data and a 129-section mouse brain reconstruction, frequently by applying global refinement after serial alignment ( Figure 2 e). Under the rich-context prompt, where we provided the problem context and commonly used packages, 89% of runs executed a published package and 54% retained one in their final submission. Agent execution traces reveal distinct problem-solving strategies Agents also differed in their workflows ( Figure 5 ). The Claude models devoted a substantial share of their time and tokens to evaluating candidate solutions and most often inspected their own alignment plots, whereas the Gemini models spent the largest share of their calls executing more, and more complex, candidate solutions ( Figure 5 a,b). gpt-6-astra was the most meticulous reviser, typically modifying its initial submission at least three times ( Figure 5 b). Among submitted solutions, gpt-6-astra had the most distinctive profile: it mostly combined simple affine transformations with numerical optimization and nonrigid warps ( Figure 5 c), all of which characterized top-performing solutions pooled across models ( Figure 5 e). Additional predictors of better performance included nearest-neighbor matching and Procrustes registration (Supplementary Note 7). Inspecting individual solutions further revealed that agents often built on existing ideas while optimizing performance more carefully and exhaustively. For example, on cross-platform and serial tasks, gpt-6-astra frequently paired an affine search on smoothed shared-gene maps with a penalized cubic B-spline warp ( Figure 5 f). This strategy builds on the two-stage registration paradigm of CAST and STalign but adds 25% held-out gene cross-validation and a positive-Jacobian fold check to prevent over-warping. Distilling agent trajectories into a standalone alignment program To test whether agent-discovered heuristics could be consolidated into a reusable, model-free algorithm, we tasked an isolated synthesis agent (Claude Code with claude-opus-5.5 ) with distilling the basic-prompt solutions and training scores of the two top-performing agents ( claude-opus-5.5 and gpt-6-astra ) into a single Python program under a five-fold cross-validation scheme ( Figure 6 a). Each synthesized program can then be applied and adapted to other alignment problems without re-querying proprietary models. Discussion We translated published spatial transcriptomics benchmarks into an auditable suite of agent tasks and systematically evaluated six frontier coding agents alongside 16 baseline methods on aligning spatial transcriptomics data. Our work highlights several core principles for evaluating AI agents in scientific workflows. First, strict environment isolation is essential: when executed on a shared filesystem, agents routinely located and exploited ground-truth files, evaluation scripts, or precomputed outputs despite explicit prompt instructions forbidding such access. Second, top-performing agents frequently matched or outperformed specialized alignment packages. Remarkably, agents achieved these results primarily by writing compact, custom numerical optimization routines rather than invoking domain-specific libraries. Moreover, equipping agents with pre-installed alignment packages and literature-derived recommendations increased computational cost without consistently improving accuracy. These findings point to broader methodological lessons for benchmarking scientific AI agents. Unlike software engineering tasks, where the desired output can often be specified by unit tests, a scientific coding task admits a broad distribution of exploratory workflows and candidate solutions. Published datasets and results offer a potentially scalable foundation for rigorous evaluation. Additionally, as in many other scientific tasks, metric choice plays a major role in our results, as widely used proxy scores can lead to different model rankings. We emphasize the importance of calibrating against ground truth to guard against metric hacking, such as over-warping in the spatial alignment example. Moreover, because execution traces record every exploratory check, failed attempt, and refinement, they enable systematic program distillation—compiling effective heuristics discovered by frontier models into fast, deterministic, and open-source scientific software. Several limitations should be considered when interpreting our results. First, we focused on spatial transcriptomics alignment; extending our publication-to-benchmark pipeline to more problems, especially open-ended biological analyses, will require domain-specific data contracts and validation checks. Second, because frontier models and command-line harnesses evolve rapidly, point-in-time rankings reflect current default vendor configurations and might change as new models are released and older ones are deprecated. This is in fact a primary motivation for our exploration of program synthesis as a path toward reproducible, vendor-independent tools. Third, although more exhaustive hyperparameter tuning of baseline packages or prompt engineering could further improve individual scores, our evaluation intentionally reflects the practical scenario in which scientists apply these tools with a limited tuning budget (or, as in our case, with agent-assisted tuning). To support transparent auditing and community benchmark development, we publicly release the Paper2Bench pipeline, all tasks, the containerized evaluation harness, and an interactive trace explorer containing all agent logs. More broadly, rather than viewing AI agents solely as black-box replacements for human analysts, we envision a collaborative paradigm in which auditable benchmarks and trace distillation harness agent exploration to build more rigorous, interpretable, and reusable tools. Dataset curation. All tasks are generated programmatically from a declarative registry. Domain-specific curation was performed across task families to ensure exact fidelity to the source publications: matching author notebook scoring modes and marker gene lists (DLPFC); recompiling Bregma slice sets, filtering ambiguous cells, and harmonizing anatomical region labels (MHPR); reconstructing slice assignments (MOp); applying published cell quality filters (whole-brain MERFISH); standardizing input coordinate frames ( Drosophila embryo); regenerating expression matrices with per-section centering and updated marker lists (Open-ST); restoring raw count matrices and linking perturbation metadata (MBSA and MBSP); anonymizing cell identifiers and permuting row order (STARmap and BARISTA-seq); and constructing lattice-corrected variants for simulated spot tasks. Coordinate unit mismatch in the published Drosophila embryo evaluation. Rebuilding the 16-section Drosophila E14–16 embryo Stereo-seq stack ( sa-019 ) [ 41 ] from raw SABench inputs uncovered a 20-fold scale discrepancy between the input coordinates and the ground-truth coordinates used in the published evaluation [ 11 ] . In SABench, input sections are centered raw Stereo-seq pixel coordinates ( raw_x , raw_y ; spatial span ∼ 600 \sim 600 units), whereas the reference ground-truth positions ( new_x , new_y ) are stored in Flysta3D 3D-atlas units that are exactly 20-fold smaller ( scale = 0.05 \text{scale}=0.05 , plus a small residual rigid rotation per section). Because SABench computed mean absolute error ( MAE \mathrm{MAE} ) directly between unscaled output coordinates and 0.05 × 0.05\times -scaled ground-truth coordinates (SABench Fig. 5f and Supplementary Table Flysta3D_MAE ), even the stationary reference slice ( s0 , which no alignment method transforms) incurred an identical floor error of 102.29 102.29 across all ten evaluated methods (reproduced to six decimal places by our scorer prior to rescaling). Consequently, under the unscaled evaluation, nearly all rigid and optimal-transport baselines and agent runs compressed tightly around the unaligned identity error, whereas methods that shrank coordinates toward the origin appeared artificially accurate ( moscot_warp , 39.8 39.8 ; cast_rescale_affine , 88.5 88.5 ). Rescaling the ground-truth coordinates by 20 × 20\times into native input pixel units resolved this artifact: the stationary reference slice has an MAE \mathrm{MAE} of 0 0 , unaligned inputs have an MAE \mathrm{MAE} of 166.3 166.3 , and alignment methods separate cleanly—led by PASTE ( 42.3 42.3 , a 75% error reduction), moscot ( 48.0 48.0 , 71%), claude-sonnet-5.5 ( 55.4 55.4 , 67%), SPACEL ( 78.4 78.4 , 53%), claude-opus-5.5 ( 118.7 118.7 , 29%), and gpt-6-astra ( 122.4 122.4 , 26%), while shrinkage configurations ( cast_rescale_affine , 217.3 217.3 ) and over-warped nonrigid runs score worse than unaligned inputs. The rich-context prompt also lists the package environments with an API example for each and the documentation menu. ## Benchmark Context (Paper-Informed Package Priority) The benchmark paper compared multiple spatial-alignment method families on related spatial-transcriptomics tasks. In this prompt variant, you are given high-level paper-derived method priorities so you can spend your package-testing budget on methods that were strongest in the paper. These are method priors, not task labels, not ground-truth transforms, and not local scorer information. You still must use only the allowed task inputs: sanitized AnnData/CSV files, spot IDs, gene expression, original ‘obsm/spatial‘ x/y coordinates, and slice identities from ‘TASK.md‘. Do not search for or use paper result tables, hidden aligned coordinates, benchmark source, scorer code, prior submissions, or withheld labels. First create a complete valid submission for every required output CSV. Then try package-backed methods in a paper-informed order. A useful package attempt means using the method-specific Python executable from ‘.method-cache/METHOD_ENVS.md‘, running an alignment API on the task data or a representative pair/subset, and recording whether it produced usable coordinates. If a high-priority method fails to import, has incompatible API/runtime behavior, exceeds a deliberate timeout, or looks worse under allowed input-only diagnostics, move on and keep the best current submission. Do not treat a quiet import as an immediate failure: several Torch/numba-heavy method envs can spend a minute or two in first-import/JIT startup. If a method needs domain labels that are not present, you may create unsupervised domains from allowed expression/coordinate data, but do not invent or recover withheld anatomical labels. ### Practical Package Guidance - Prefer ‘spateo‘ and ‘SPACEL‘ when tissue geometry, non-rigid deformation, or image-like spatial continuity looks important. - Prefer ‘PASTE2‘ when partial overlap, NGS/Visium-style slices, or robust optimal-transport matching looks important. - Keep ‘PASTE‘ as a simpler/faster fallback, especially for large serial stacks where full package methods are too slow. - Use ‘CAST‘, ‘STAIR‘, or ‘SLAT‘ when their APIs are importable and the task looks compatible with embedding or graph matching. - Treat ‘GPSA‘, ‘STAligner‘, ‘STalign‘, and ‘SANTO‘ as optional method-specific attempts rather than first defaults unless their API/docs clearly fit the task. - For slower method families, run a small representative pair/subset first and allow enough time for first import/JIT startup before deciding the method is infeasible. ### Required Reporting In ‘submission/report.json‘ or a local note, record: - which paper-prior methods you attempted, - which package env executable you used, - whether the package produced usable transformed coordinates, - why you moved on from any failed high-priority method, - which candidate you finally submitted.
